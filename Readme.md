# AR Engineering

Android-прототип осмотра насоса с HUD варианта B. В серверном режиме приложение ищет карточку по QR, восьмизначному номеру или ручному выбору, показывает паспорт и проверяет визуальные признаки. Камеру ведёт ARCore, модели YOLO работают на телефоне. FastAPI на ноутбуке хранит цифровой двойник, замеры и отчёты в SQLite.

[Общее описание проекта, запуск и сверка с ТЗ](docs/PROJECT.md). [API интерфейса](docs/UI_API.md) описывает контракт Compose и контроллера.

[Плагин для Figma](design/figma/README.md) создаёт редактируемые экраны и прототип осмотра.

Требования к сборке и телефону описаны в [REQUIREMENTS.md](REQUIREMENTS.md). Подключение UI к серверным данным описано в [инструкции для команды](docs/INTEGRATION.md). Контекст для агентов находится в [AGENTS.md](AGENTS.md), переписка и макет — в [docs/CHAT.md](docs/CHAT.md).

## Инструменты

- Kotlin и Jetpack Compose для приложения и интерфейса.
- Google ARCore 1.57.0 для кадров камеры, трекинга по видео и данным IMU, поиска поверхности и 3D-якорей. На поддерживаемых устройствах используется Depth API.
- OpenGL ES 2.0 для вывода видеопотока ARCore.
- ONNX Runtime Android и три модели YOLO11n для насоса, ориентиров и коррозии. ML Kit читает QR и цифровое поле шильдика.
- Android Studio, Android SDK 36, Android Gradle Plugin 9.2.1 и Gradle Wrapper 9.4.1 для сборки. Можно использовать JDK из Android Studio.
- ADB для установки APK и чтения журналов.

## Запуск

Откройте эту папку в Android Studio, выберите смартфон с поддержкой ARCore и запустите конфигурацию `app`. Разрешите камеру. По запросу установите или обновите Google Play Services для AR.

Для сборки из PowerShell задайте `JAVA_HOME` и `ANDROID_HOME`, если они ещё не настроены, и выполните:

```powershell
.\gradlew.bat :app:assembleDebug :app:lintDebug
```

Отладочный APK появится в `app/build/outputs/apk/debug/app-debug.apk`.

## Локальная телеметрия

Для прогона с ноутбуком есть отдельный [сервер FastAPI и SQLite](server/README.md) с цифровыми двойниками, авторизацией и отчётами.

Room импортирует 500 пар замеров оборудования №1 из `app/src/main/assets/telemetry/pump-1.tsv`. Файл подготовлен из двух таблиц XLSX в `dbLoop` по совпадающим дате и оборотам. При обновлении приложения с версии схемы 1 существующие записи сохраняются.

Пока процесс приложения работает, воспроизведение выдаёт одну пару замеров в секунду и после последней возвращается к первой. Время замера соответствует исходной записи без часового пояса. Время обновления берётся с устройства. Колонка `source_diagnosis` хранит исходную подпись из таблицы.

Чтобы увидеть результат, нажми «?» сверху, введи `pasport` и нажми «Выполнить». В локальном режиме терминал показывает текущие значения, диагнозы из таблиц и уставки из описаний в `dbLoop`. Показания обновляются, пока паспорт открыт. Для проверки с ноутбуком используй команды из [инструкции к серверу](server/README.md#проверка-с-android).

Интеграция с логикой осмотра может читать поток `observeCurrent(equipmentId)` через `InspectionApplication.telemetryDatabase.telemetry()`. Методы `vibrationReadings(equipmentId)` и `temperatureReadings(equipmentId)` возвращают исходные замеры по времени. ID оборудования передаётся строкой `"1"`.

## Проверка метки

1. Войдите в деморежим и на экране QR откройте «Проверить AR-метку». Наведите камеру на неподвижную деталь с заметной текстурой. Плавно сместите телефон вбок, затем коснитесь конкретной точки на детали.
2. Проверьте, что стрелка указывает на ту же точку при шаге вбок, приближении, смене ракурса и повороте экрана.
3. Кратко закройте камеру или отведите её от детали, затем вернитесь к исходному ракурсу. При потере трекинга метка скрывается. Если трекинг восстановился в текущей сессии, она появляется снова.
4. Коснитесь другой поверхности, чтобы переставить метку, или нажмите «Убрать метку».

Ручная метка привязана к поверхности. В серверном режиме CV отдельно показывает короткоживущие 2D-рамки и ориентир рамы при подходящем кадре.
