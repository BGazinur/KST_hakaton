Подключение к KST_hakaton

Точка подключения — app/src/main/java/com/arengineering/inspection/ArPreview.kt,
в существующем renderer сразу после session.update(), на том же GL-потоке.
Точное место легко найти по val frame = session.update(). Продолжать использовать
существующие BackgroundRenderer, setDisplayGeometry и проекцию ручной метки.
Не открывать CameraX/Camera2 параллельно ARCore. Не менять геометрию камеры ради
416px модели: вход подготавливает библиотека.

1. Добавить Gradle module по README. Базовые версии: SDK36/min24, AGP9.2.1,
   Gradle9.4.1, ARCore1.57.0, ORT Android1.23.2. JDK21 использован при проверке.
   androidResources.noCompress должен содержать onnx в app, не только в cv;
   это включено в integration/gradle.patch. Первоначальный CPU baseline:
   два intra-op потока, один inter-op; ускорители отдельно тестировать по parity.

2. Использовать examples/BridgeIntegrationExample.kt как пример проводки.
   Его можно скопировать в пакет com.arengineering.inspection.cv внутри app;
   он не содержит UI и вызывает переданные callbacks. Ленивая инициализация
   OrtPumpEngine, analyze и close выполняются на одном выделенном worker.
   assets loader: { path -> context.assets.open(path).use { it.readBytes() } }.
   context хранить applicationContext, а не уничтоженную Activity.

3. На каждом session.update() вызывать afterSessionUpdate, даже если предыдущая
   модель ещё работает. Адаптер сам пропускает кадры, не накапливает очередь.
   acquireCameraImage и копия planes выполняются на GL; Image.close() — сразу
   в finally, до фонового RGB/resize/inference. Frame/Camera/live intrinsics не
   передаются worker. Учитываются pixelStride, rowStride, ByteBuffer.position,
   cropRect. Не превращать Image в JPEG. YUV→RGB здесь BT.601 limited-range;
   фактический цвет/ориентацию обязательно сверить на целевом телефоне.

4. Передавать geometryEpoch, увеличиваемый при смене viewport/surface rotation/
   display geometry, и inspectionEpoch при смене QR, зоны, этапа и сбросе осмотра.
   На pause очищать UI и вызывать pauseOrChangeInspection(), затем штатный
   порядок pause GLSurfaceView/Session из приложения. Bridge не владеет Session.
   На окончательном destroy закрыть bridge. Новый GL-thread/Session lifecycle —
   новый объект интеграции. Закрытие ORT будет поставлено после текущей задачи.

5. publishStatusAndCandidateList обновляет только текст/список предложенных зон.
   Этот результат не даёт разрешения рисовать старую маску на текущем кадре.
   publishOverlay получает только результат, прошедший отдельный spatial gate,
   либо null. Null немедленно очищает текущие CV-слои. UI state менять на UI
   потоке через Handler/Compose state dispatcher; GL callbacks нельзя считать UI.
   showRejection и takeFailure выводить через русские strings.xml. Технические
   exception strings хранить в диагностике, не показывать как обычный сценарий.

Контур и движение камеры
Модель выдаёт 2D-силуэт на исходном CPU-кадре. Полный силуэт не становится
3D-поверхностью от создания одного Anchor. Для строгой политики
OverlayPolicy.SOURCE_FRAME_ONLY контур допустим только на том же timestamp.
В асинхронном живом потоке он обычно уже устарел, поэтому эта политика часто
не покажет контур. Это осознанное ограничение данного варианта интеграции.

Для демонстрационного живого контура у неподвижного насоса можно явно выбрать
OverlayPolicy.APPROXIMATE_STATIONARY_REFERENCE. Нужен отдельный tracking
reference Anchor в окружении насоса. Gate допускает не более1см перемещения
и1° поворота камеры с момента анализа плюс TTL250ms. При движении или потере
reference контур скрывается. Даже в этих пределах это приблизительное
2D-совмещение: глубина неизвестна, точность не гарантируется. Три точки из
pose имеют те же ограничения. Не называть этот режим точной AR-сегментацией.

Для точного живого контура при движении нужен следующий этап: same-source depth
или поверхность/mesh, привязанная к якорю, и reprojection с проверкой occlusion,
либо верифицированный temporal tracker. В этот пакет такая реконструкция не
включена. Сохранять кадры для этого не требуется. Существующий фон камеры
продолжает идти без замораживания/снимков при любой политике overlay.

Постановка подтверждённой пространственной точки
Reference Anchor и выбранная пользователем метка — разные объекты с отдельным
владением. Приложение может сначала получить reference обычным касанием
поверхности рядом с насосом (штатная ручная функция репозитория), сохранить его
отдельно и затем передавать в bridge. Перенос/удаление amber marker не должен
удалять reference. Сам bridge ни создаёт, ни удаляет якоря.

Если старт по QR должен обходиться без дополнительного касания, приложение
может создать невидимый reference один раз при начале осмотра на GL, когда
camera.trackingState == TRACKING: session.createAnchor(frame.camera.pose).
Это фиксирует локальную опору в текущей позиции камеры; это НЕ метка насоса
или найденного дефекта. Не пересоздавать такую опору на каждом кадре. Сохранить
её в AR owner, передавать в bridge, detach при завершении/смене осмотра.
Пример минимальной операции на GL при новом inspectionEpoch:
  referenceAnchor?.detach()
  referenceAnchor = session.createAnchor(frame.camera.pose)
Для привязки к обнаруженной поверхности можно использовать штатное касание.
Оба способа требуют физической проверки устойчивости; выбор не улучшает
точность YOLO и не превращает маску в 3D-модель.

На UI пользователь подтверждает конкретный ZoneCandidate из текущего списка;
confirmCandidate создаёт ConfirmedSelection с точным stamp/координатой/ID.
Команда атомарно передаётся GL, не переиспользует нормированные экранные
координаты старой модели в MarkerCommand.Place текущего кадра.

Bridge сохраняет sourceCamera относительно sourceReference:
  relative = sourceReferencePose.inverse().compose(sourceCameraPose)
На текущем кадре:
  sourceCameraInCurrentWorld = currentReferencePose.compose(relative)
  directionCamera = [(x*W-cx)/fx, -(y*H-cy)/fy, -1]
После вращения в текущий world выполняется frame.hitTest(origin,0,direction,0).
ARCore может уточнять мировую систему между кадрами, поэтому сырой сохранённой
cameraPose для этого недостаточно. Знаки y/z соответствуют ARCore/OpenGL.

proposeSelectedHit проверяет тот же session/epochs/capture, возраст, tracking,
выбранный candidate, crop, reference и поверхность. При нескольких разделённых
слоях, отсутствии поверхности или выходе за экран возвращает Rejected.
REFERENCE_REQUIRED означает, что можно показать текст результата, но нельзя
ставить пространственную метку по этому старому кадру.

При AnchorProposal.Ready создать hit.createAnchor() сразу в callback на том же
GL-кадре. Это принадлежит Android-приложению: обновить существующий marker owner,
отсоединить прежний marker, сохранить reference. Использовать штатную проекцию
нового anchor; при PAUSED скрыть, при STOPPED убрать/предложить новую постановку.
Plane/hit не доказывает, что это нужная деталь: оператор проверяет положение.
Если в момент подтверждения capture устарел или сменился контекст осмотра,
предложить подтвердить свежий результат. Более новый результат сам по себе
не отменяет ещё допустимый source capture. Не подменять исходную точку
кандидатом другого кадра.

Режим крупного плана
После выбора рамы переключить CvMode.DETAIL_RUST с новым inspectionEpoch.
Модель сегментирует весь новый кадр, поэтому приложение должно вести оператора
к выбранной зоне и проверять, что она остаётся в поле зрения. Изменение цвета
карточки/рамки — наличие кандидата; окончательное решение отдельно подтверждает
оператор. На смене зоны, потере трекинга и reset очистить метаданные/overlay.
История изображений, QR-библиотека, карточки оборудования и отчёты здесь не
реализованы: это отдельные функции команды Android/backend.

Что проверить на физическом телефоне
Оба поворота экрана, шаг вбок/приближение, новый QR/зона, пауза Activity,
закрытие камеры/потеря tracking, отсутствие поверхности и нескольких насосов.
Проверить YUV цвета, совпадение CPU Image timestamp и intrinsics, задержку p50/p95,
частоту анализа, память/нагрев за5мин; записывать метрики без сохранения кадров.
Удержание amber marker проверить штатной процедурой Readme репозитория.
Физическое устройство в этой проверке не использовалось; результат не заявлен.
