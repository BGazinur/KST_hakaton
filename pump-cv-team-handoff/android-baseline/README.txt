Это модуль для интеграции, а не готовый экран приложения. Содержит три обученные
ONNX-модели, Kotlin-инференс и декодер, адаптер ARCore, контракт результата,
примеры и тесты. Веса перенесены из предыдущего пакета без переобучения.
Изменены мобильный runtime, геометрия, формат маски и обработка устаревших кадров.
Точность на реальном насосе этим изменением не улучшена; см. MODEL_CARD.txt.

Что передать Android-разработчику
1. Целиком этот архив. android/ — готовый исходный Gradle library module.
2. ARCORE_INTEGRATION.txt — порядок подключения к существующему AR-рендереру.
3. contract/result.schema.json, RESULT_FORMAT.txt и examples/results/ — контракт.
4. contract/model-manifest.json — контрольные суммы, тензоры, пороги и классы.
5. VALIDATION.txt — фактическая проверка и оставшаяся проверка на телефоне.

Быстрое подключение
Скопировать android/ в корень Android-репозитория под именем cv/.
В settings.gradle.kts добавить include(":cv").
В app/build.gradle.kts, dependencies: implementation(project(":cv")).
В android{} того же app/build.gradle.kts: androidResources { noCompress += "onnx" }.
Эта настройка library-модуля не передаётся упаковщику приложения автоматически.
Правки подготовлены в integration/gradle.patch (проверен на указанном commit):
из корня репозитория можно выполнить git apply ПУТЬ/К/integration/gradle.patch.
Модели уже лежат в cv/src/main/assets/cv/; скачивать их в приложении не нужно.
Не добавлять отдельный Kotlin Android plugin: AGP 9 использует встроенный Kotlin.
Существующие Gradle Wrapper, ARCore, Compose и UI B сохранить.

Проверка:
  .\gradlew.bat :app:assembleDebug :app:lintDebug :cv:testDebugUnitTest :cv:lintDebug
  (macOS/Linux: ./gradlew с теми же задачами)

Сценарий приложения
QR/код выбирает запись оборудования и запускает новый inspectionEpoch. Сам
QR-декодер/каталог остаётся ответственностью приложения; CV распознаёт класс
насосного агрегата, а не серийный номер. На нескольких насосах нельзя назначать
код ближайшей рамке автоматически: вернуть AMBIGUOUS и дать выбрать оборудование.

OVERVIEW: pump-seg + pump-pose → контур агрегата и до трёх видимых зон осмотра.
Зона — предложение для наведения, НЕ найденный дефект. Если точка не прошла
порог/проверку маски, она отсутствует. Не дорисовывать точку по шаблону.

После выбора рамы и приближения: увеличить inspectionEpoch, DETAIL_RUST →
маска визуального признака коррозии. В новом режиме очищаются результаты общего
плана. Приложение подтверждает, что крупный план относится к выбранной зоне:
одна модель коррозии не устанавливает принадлежность пятна конкретному насосу.
Для корпуса/клеммной коробки пока DETAIL_UNSUPPORTED, ручной осмотр.

Обработка только потока: ARCore CPU Image → копия YUV в RAM → RGB → ONNX →
результат. В модуле нет открытия второй камеры, JPEG, кнопки снимка, записи
изображений, загрузки кадров или сетевых вызовов. Тестовые RGB в src/test —
ранее существовавшие контрольные изображения; в APK они не включаются.

Реальные ограничения для защиты
Можно демонстрировать локальный инференс, силуэт, предложения зон и коррозию.
Автоматическую точную 3D-привязку всех зон с любого ракурса пакет не доказывает.
Модель ориентиров слаба на новых реальных насосах. 3D-якорь удерживает выбранную
пользователем точку неподвижной поверхности, а не автоматически весь силуэт.
Работа AR и скорость на физическом телефоне пока не проверены.
