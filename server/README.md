# Серверная база AR Engineering

Сервер хранит цифровые двойники оборудования, учётные записи и историю осмотров в SQLite. Файл базы по умолчанию — `server/data/inspection.db`. Android-приложение может обращаться к API по локальной сети.

[Словарь таблиц и схема связей](../docs/DATABASE.md)

## Запуск

Команды выполняются из корня репозитория. Нужен Python 3.11 или новее. На Windows:

```powershell
python -m venv server/.venv
.\server\.venv\Scripts\python.exe -m pip install -r server/requirements.txt
.\server\.venv\Scripts\python.exe -m server.manage init
.\server\.venv\Scripts\python.exe -m server.manage create-user engineer@example.com --name "Инженер" --role engineer
.\server\.venv\Scripts\python.exe -m uvicorn server.api:app --host 0.0.0.0 --port 8000
```

На Linux используй `server/.venv/bin/python` вместо Windows-пути. Пароль вводится в консоли. Можно задать другой файл базы через `INSPECTION_DB`. Запускай один процесс Uvicorn, чтобы у насоса был один цикл воспроизведения.

API и база работают без интернета после установки зависимостей. С телефона в той же сети используй локальный IP ноутбука. Если компьютер не пропускает запросы, проверь входящий порт 8000 в частной сети. Описание API в JSON доступно локально по `http://127.0.0.1:8000/openapi.json`. Страница Swagger по адресу `http://127.0.0.1:8000/docs` загружает интерфейс с CDN и требует интернета. Для теста по HTTP используй отдельную сеть команды и демонстрационные учётные записи. Для рабочих учётных записей трафик авторизации нужно защищать HTTPS.

## Что хранится

- `users` и `sessions` хранят локальные учётные записи, роли, хеши паролей Argon2 и хеши токенов доступа. Сессия действует 12 часов. Внешний почтовый сервис для входа не нужен.
- `equipment` служит корнем цифрового двойника. Карточка включает паспортные характеристики, дочерние узлы, идентификаторы, режимные карты, копии документов и историю. `equipment_lines` и `line_equipment` хранят состав линии по направлению потока.
- `sensors`, `telemetry_samples`, `current_telemetry` и `operating_state` хранят датчики, уставки, замеры и состояние оборудования. Насос №1 воспроизводит 500 пар замеров из `dbLoop` по одной паре в секунду. Сервер импортирует общий файл Android `app/src/main/assets/telemetry/pump-1.tsv`. Исходная дата и время обновления хранятся отдельно. Паспорт сравнивает показания с заданными уставками, а исходный диагноз из таблиц сохранён как справочное поле.
- `maintenance_plans` и `maintenance_events` хранят регламенты и выполненные работы. `equipment_tests` хранит результаты испытаний и метрологических поверок, а файлы протоколов лежат в `documents`. В паспорте статус срока ТО вычисляется по ближайшему заданному сроку или порогу моточасов.
- `defect_types` содержит 22 признака из описания заказчика. `inspection_checks` содержит инструкции, критерий пригодности и рекомендации для шагов осмотра. Это разные сущности, поскольку один визуальный признак может проверяться в разных сценариях.
- `reports` и `report_items` фиксируют автора, комментарий, снимок паспорта, измерения с уставками и результаты по шагам. `report_attachments` хранит загруженные фото. PDF и Excel формируются по запросу.

Демонстрационная линия состоит из входной задвижки, насоса №1, обратного клапана и выходной задвижки. Модель и серийный номер насоса оставлены пустыми до получения паспорта этого агрегата. Уставки взяты из описаний в `dbLoop`. Значения 3950 моточасов, порог ТО 4000 и окно предупреждения 100 моточасов — демонстрационные. При этих значениях паспорт показывает `due_soon` и 50 моточасов до ТО. Текущее значение моточасов хранится отдельно от ускоренного проигрывания часовых записей.

## Вызовы для приложения

[Инструкция для разработчиков UI и YOLO](../docs/INTEGRATION.md) описывает, какие поля использовать на экранах и как согласовать формат кадров и детекций.

1. `POST /auth/login` принимает JSON с полями `email` и `password`. В остальных запросах передавай заголовок `Authorization: Bearer <access_token>`. `GET /auth/me` возвращает профиль, `POST /auth/logout` отзывает токен.
2. `GET /equipment/resolve?kind=qr&value=DEMO-PUMP-001` возвращает ID. Для шильдика используется `kind=nameplate`. Модель CV может определить тип оборудования, а конкретный экземпляр выбирается по считанному идентификатору или известному ID.
3. `GET /equipment/1/passport` возвращает цифровой двойник, текущий замер, нормы и будущие проверки. Для скачивания копии документа используй `GET /documents/{id}`.
4. `POST /reports` принимает `equipment_id`, `notes` и список `items` с полями `check_id`, `outcome` и `observation`. Передай `telemetry_sample_id` из `telemetry.id` паспорта, чтобы сохранить именно показания начала осмотра. При пропуске поля сохраняется текущий замер на момент создания отчёта.
5. `GET /equipment/1/reports` возвращает историю, `GET /reports/{id}` возвращает сохранённый отчёт со снимком замеров и шагами. Инженер видит свои отчёты, мастер и администратор видят отчёты команды. `GET /defect-types` возвращает справочник признаков.

Пример сохранения после входа, если пользователь действительно прошёл шаг из паспорта:

```json
{
  "equipment_id": 1,
  "telemetry_sample_id": 1,
  "notes": "Осмотр корпуса",
  "items": [
    { "check_id": 1, "outcome": "no_visible_issue", "observation": "Видимой влаги нет" }
  ]
}
```

Чтобы прикрепить полученную от заказчика копию паспорта или регламента к нужному оборудованию, запусти `python -m server.manage add-document 1 путь-к-файлу.pdf --kind manual --title "Руководство по эксплуатации"` через Python из окружения сервера.

## Проверка с Android

1. Запусти сервер с `--host 0.0.0.0` и подключи телефон к той же локальной сети. Посмотри IPv4 ноутбука через `ipconfig`.
2. В отладочном APK открой «?» и введи `server http://192.168.1.10:8000`, подставив IP ноутбука. При успешном подключении терминал покажет `HTTP 200` и `{"status":"ok"}`.
3. Введи `login engineer@example.com` с почтой созданной учётной записи, затем введи пароль в отдельном поле.
4. `pasport 1` показывает JSON паспорта. `watch 1` обновляет его примерно раз в секунду. Следующая команда останавливает обновление.
5. `checks 1` показывает узлы, сценарии осмотра и ID проверок. `savecheck 1 1 no_visible_issue` сохраняет проверку №1 насоса №1 как результат ручного осмотра. Команда возвращает ID созданного отчёта. `report 1` читает отчёт по его ID.
6. `logout` отзывает серверную сессию. `local` переключает терминал обратно на Room.

HTTP доступен в отладочном APK для локального теста. Сетевые команды работают через терминал «?». Загрузка поверок, фото и скачивание файлов пока доступны через API.

## Поверки датчиков

Войдите под мастером или администратором. Для насоса №1 код датчика температуры подшипника — `pump_bearing_c`. Коды остальных датчиков приходят в `sensors[].code` паспорта.

```powershell
curl.exe -H "Authorization: Bearer $inspectionToken" -F "sensor_code=pump_bearing_c" -F "title=Поверка датчика температуры" -F "performed_at=2026-11-13" -F "valid_until=2027-11-13" -F "outcome=pass" -F "certificate_number=П-001" -F "protocol=@C:/path/protocol.pdf" http://127.0.0.1:8000/equipment/1/verifications
```

`$inspectionToken` — токен из `POST /auth/login`. Замените даты, номер и путь данными своего протокола. Поля `certificate_number`, `valid_until`, `details` и PDF `protocol` необязательны. Для результата используйте `pass`, `fail` или `inconclusive`. Срок действия указывается только для успешной поверки. Максимальный размер PDF — 10 МБ.

`GET /equipment/{id}/verifications` возвращает историю поверок от новых к старым. Если прикреплён протокол, его ID приходит в `protocol_document_id`. Скачайте его через `GET /documents/{id}`. Поверки также видны в `tests` цифрового двойника. Срок действия поверки хранится в её записи. Регламент и календарный срок следующей поверки ведутся в `maintenance_plans` отдельно.

## Фотографии и выгрузка отчёта

1. Создайте отчёт через `POST /reports`.
2. Отправьте фото как `multipart/form-data` в `POST /reports/{id}/photos`. Поле `photo` принимает JPEG или PNG до 5 МБ. Необязательный `check_id` прикрепит фото к шагу, который входит в отчёт.
3. Список вложений приходит в поле `attachments` ответа `GET /reports/{id}`. Файл скачивается через `GET /reports/{id}/attachments/{attachment_id}`.
4. `GET /reports/{id}/export/pdf` и `GET /reports/{id}/export/xlsx` возвращают файлы со сведениями об оборудовании, замерами и уставками, результатами осмотра и именами приложенных фото. Сами фотографии доступны отдельными файлами.

Для PDF сервер автоматически использует доступный системный TrueType-шрифт с кириллицей. При необходимости задайте путь к шрифту через `INSPECTION_PDF_FONT`. При запуске сервер автоматически обновит схему SQLite до версии 2. В старых отчётах выгружаются сохранённые показания. Исторические уставки появятся в новых отчётах после обновления.
