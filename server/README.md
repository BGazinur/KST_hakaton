# Локальный сервер AR Engineering

Нужен Python 3.11 или новее. Выполните из корня репозитория в PowerShell:

```powershell
python -m venv server/.venv
.\server\.venv\Scripts\python.exe -m pip install -r server/requirements.txt
.\server\.venv\Scripts\python.exe -m server.manage init
.\server\.venv\Scripts\python.exe -m server.manage create-user admin@example.com --name "Администратор" --role admin
.\server\.venv\Scripts\python.exe -m uvicorn server.api:app --host 0.0.0.0 --port 8000
```

Замените адрес администратора своим. CLI попросит пароль длиной 12–128 символов и его подтверждение. Если администратор уже есть, повторно создавать его не нужно. На Linux используйте `server/.venv/bin/python`.

Сервер использует один процесс для воспроизведения телеметрии насоса №1. SQLite хранится в `server/data/inspection.db`. Переменная `INSPECTION_DB` позволяет использовать другой файл. При запуске сервер создаёт демонстрационную базу или обновляет схему существующей. Пользователи и отчёты сохраняются.

## Панель в браузере

На ноутбуке откройте [http://127.0.0.1:8000/panel](http://127.0.0.1:8000/panel). На другом устройстве в той же сети подставьте IPv4 ноутбука вместо `127.0.0.1`. Если подключение блокируется, проверьте входящий порт 8000 в частной сети. Панель, Android API и база работают без интернета после установки зависимостей. Для демонстрации по HTTP используйте отдельную локальную сеть и демонстрационные пароли. Для рабочих учётных записей используйте HTTPS.

- Инженер видит паспорта, замеры, документы и свои отчёты.
- Мастер также видит отчёты команды и может сохранять поверки датчиков с PDF-протоколами.
- Администратор может добавлять пользователей, оборудование и узлы, датчики, замеры, шаги осмотра, документы и поверки. Откройте нужную карточку и раздел «Добавить данные». PDF-документы принимаются до 10 МБ.

Внесённый замер становится текущим, если он новее уже внесённого. Для насоса №1 первый внесённый замер приостанавливает демонстрационный поток. Кнопка «Возобновить демонстрацию» возвращает воспроизведение. Внесённые значения остаются в истории.

## Подключение Android

Введите адрес сервера, например `http://192.168.1.10:8000`, и войдите под локальной учётной записью. Для насоса №1 доступны QR `DEMO-PUMP-001`, номер шильдика `00123456` и ручной выбор. В терминале «?» команда `pasport 1` показывает тот же паспорт, а `watch 1` обновляет его.

Кнопка «Сохранить PDF» доступна после осмотра и в истории. PDF использует сохранённые на момент осмотра показания. Если на сервере нужен другой шрифт с кириллицей, укажите файл TrueType в `INSPECTION_PDF_FONT`. Контракт API доступен через `/openapi.json`.

## Локальная модель

Скачайте `Qwen3VL-2B-Instruct-Q4_K_M.gguf` и `mmproj-Qwen3VL-2B-Instruct-Q8_0.gguf` в `server/data/qwen`. Распакуйте Windows x64 Vulkan-сборку llama.cpp в `server/data/qwen/runtime`. [Веса модели](https://huggingface.co/Qwen/Qwen3-VL-2B-Instruct-GGUF/tree/52d6c8ffea26cc873ac5ad116f8631268d7eb503) · [llama.cpp b12383](https://github.com/ggml-org/llama.cpp/releases/tag/b12383)

Во втором окне PowerShell запустите:

```powershell
.\server\start-qwen.ps1
```

По умолчанию используется `Vulkan1`, соответствующий RTX 4060 на ноутбуке команды. Чтобы выбрать другой адаптер, проверьте список устройств через `llama-server.exe --list-devices` и укажите его через `-Device`. Сервер модели слушает `127.0.0.1:8081`.

На шаге осмотра нажмите «Проверить кадр локальной моделью». Приложение передаст кадр с камеры. Если модель заметит признак, инженер может добавить наблюдение к шагу. После сохранения осмотра наблюдение попадёт в отчёт и PDF. Ручной осмотр и экспорт доступны при остановленной модели.
