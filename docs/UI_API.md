# API интерфейса осмотра

[InspectionUiApi.kt](../app/src/main/java/com/arengineering/inspection/InspectionUiApi.kt) — Kotlin-контракт между Compose и логикой приложения. Контроллер публикует `StateFlow<InspectionUiState>` и принимает намерения пользователя через `dispatch(InspectionAction)`. В [серверном режиме](UI_BACKEND.md) `BackendInspectionController` подключает авторизацию, каталог, ручной осмотр и отчёты. `DemoInspectionController` остаётся для автономного демо. Таблица ниже описывает целевой сценарий, включая ещё не подключённые QR и CV.

`dispatch` вызывается из основного потока и должен возвращаться сразу. Чтение базы, анализ и запись выполняются в фоне. Контроллер сериализует переходы, игнорирует повторные нажатия и запоздалые результаты, публикует новый снимок после каждого перехода. Тексты данных, инструкций и ошибок передаются в готовом для показа виде. Идентификаторы оборудования, узлов, неисправностей, снимков и отчётов должны быть стабильными.

## Сценарий и события

| Состояние или условие | Действия UI | Что публикует контроллер |
| --- | --- | --- |
| `account == null` | `SignIn(login, password)` | `signingIn`, `signInError` или заполненный `account`. При запуске восстановите подтверждённую сессию. Камера запускается только в активном приложении после появления аккаунта. |
| Аккаунт открыт | `SignOut` | Отмените операции активного осмотра, очистите состояние и сессию. При `account == null` Activity закрывает ARCore. |
| `ScanQr` | `ScanAgain`, `OpenEquipmentPicker` | QR-адаптер передаёт декодированное значение контроллеру. После поиска в каталоге заполните `equipment` и перейдите в `EquipmentPreview`. Для неизвестного кода верните `ScanQr(error)`. |
| `PickEquipment` | `SelectEquipment(id)`, `ScanAgain` | Отдайте список, признак загрузки или ошибку. После выбора загрузите карточку и покажите то же превью. `ScanAgain` возвращает к рамке QR. |
| `EquipmentPreview` | `StartInspection` | Перейдите в `Analyzing`, загрузите снимок телеметрии и оцените правила. Затем опубликуйте `AnalysisReady` и текущие предупреждения. При недостатке данных установите `missingData`. |
| `AnalysisReady` | `ContinueInspection` | Перейдите в `FindPump`. При пустой очереди узлов можно сразу перейти к `Summary`. |
| `FindPump` | Распознавание запускается контроллером | Примите результат CV для выбранного насоса, заполните контур при наличии и перейдите к первому `InspectNode`. |
| `InspectNode` | `SkipNode(stepId)`, `NextNode(stepId)` | Нумерация с 1. Сохраняйте порядок, заданный правилами. При плохом кадре передайте `guidance`, при принятом результате — `result`. `NextNode` допустим после результата, `SkipNode` до него. Последний переход открывает `Summary`. |
| `Summary` | `SaveReport(reportId, note)`, `NewInspection` | Сохраняйте по ID отчёта идемпотентно. Установите `saving` на время записи и `saved` только после её успеха. В том же снимке обновите `history`. Ошибка записи остаётся в `Summary.error`. |

Панель, диалоги и их навигация живут в Compose. `equipment.previousFindings` содержит открытые записи прошлых осмотров. `findings` содержит предупреждения текущего осмотра. `SENSOR` обозначает предупреждение по телеметрии, `REGULATION` — по регламенту. Красный значок появляется при наличии записи `SENSOR`. Успешные и пропущенные проверки передаются только в `InspectionReport.results`. Необязательная уверенность CV задаётся числом от 0 до 1.

В `ComponentCard.fields` передавайте доступные характеристики, даты установки, замены и обслуживания, норматив и оценку остаточного ресурса отдельными полями. В `EquipmentCard.telemetry` передавайте показания и уставки с единицами. `InspectionReport.telemetry` хранит снимок на момент проверки. `timestampMillis` — Unix-время в миллисекундах.

## Камера, CV и AR

- `ArPreview` владеет рендером ARCore. Подключите захват кадров на стороне этого модуля. Копируйте данные из CPU-изображения в ограниченный буфер и своевременно закрывайте `Image`. Само распознавание запускайте вне GL-потока. Используйте ARCore как источник кадра и позы.
- Передавайте CV идентификаторы осмотра и узла, временную метку кадра в наносекундах и параметры преобразования изображения. Применяйте результат только к тому осмотру и шагу, для которых кадр был захвачен. Учитывайте поворот, кроп модели, обрезку камеры и актуальную геометрию viewport.
- За постановку и сопровождение 3D-якорей отвечает AR-адаптер. Используйте позу и геометрию кадра анализа при привязке к поверхности. Обновляйте проекцию при движении камеры. Для контура и указателей `InspectionOverlay` принимает нормализованные координаты полного viewport камеры с началом в левом верхнем углу. `(0, 0)` — верхний левый угол, `(1, 1)` — нижний правый. Контур передаётся упорядоченным списком вершин. Передавайте только конечные координаты, а при смене viewport, потере трекинга, смене узла или выходе точки из кадра удаляйте устаревшие отметки из состояния.
- Для принятого результата автоматически сохраняйте использованные CV кадры. Передавайте в `StepResult.evidence` устойчивый локальный URI и исходный `frameTimestampNanos`. UI показывает количество прикреплённых кадров в истории. Кнопка «Отправить отчёт» сохраняет запись через контроллер, после успеха интерфейс показывает «Отчёт отправлен» на том же экране.

## Проверка на демоданных

1. Введите вымышленные непустые логин и пароль. В деморежиме можно пройти сценарий даже без доступной камеры.
2. Выберите «Использовать демо-QR» или «Выбрать вручную». Проверьте превью и доступ к полной карточке из превью и боковой панели.
3. Начните проверку. После анализа откройте предупреждения через красный значок, вернитесь и нажмите «Продолжить проверку».
4. Используйте демокнопки для распознавания насоса и узлов. Проверьте «Далее» и «Пропустить узел».
5. Добавьте заметку, сохраните отчёт и найдите его в истории. Выйдите через аккаунт. Для проверки пространственной привязки на телефоне используйте «Проверить AR-метку» на экране QR и сценарий из [Readme.md](../Readme.md#проверка-метки).

Демоконтроллер сохраняет признак входа и логин между запусками. Результаты анализа вымышлены. Добавленные демоотчёты доступны в истории до завершения процесса приложения. QR-декодер, CV, база оборудования и реальные кадры отчёта подключаются командой через описанный контракт.
