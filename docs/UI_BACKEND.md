# Проверка интеграции UI и backend

Актуальный общий сценарий после подключения CV и сверка с ТЗ описаны в [PROJECT.md](PROJECT.md). Этот документ фиксирует серверный ручной сценарий на этапе объединения UI и backend.

Серверный режим открывается по умолчанию. В отладочном APK введите адрес ноутбука, почту и пароль учётной записи сервера. Например, `http://192.168.1.10:8000`. Для эмулятора на том же компьютере используйте `http://10.0.2.2:8000`. Запуск сервера описан в [server/README.md](../server/README.md). Деморежим доступен с экрана входа. Кнопка «?» открывает диагностический терминал.

## Связанный сценарий

1. Вход через `POST /auth/login` и профиль через `GET /auth/me`.
2. Ручной выбор оборудования из `GET /equipment`. Сервер возвращает самостоятельные агрегаты линии, дочерние узлы остаются в паспорте.
3. Паспорт, история отчётов, показания и уставки из SQLite. Для осмотра подойдёт демонстрационный насос №1, у него два серверных шага: зона вала и защитный кожух муфты.
4. «Начать проверку» фиксирует снимок телеметрии. Предупреждения берутся из статусов датчиков и регламентов. Инженер указывает результат каждого шага вручную или пропускает его. Автоматического выбора проверок по тревоге пока нет.
5. Отчёт сохраняется в SQLite с ID исходного замера, результатами и заметкой. UI читает сохранённый отчёт обратно. Повторная отправка с тем же `client_request_id` возвращает существующий ID для того же автора. Миграция SQLite до версии 3 сохраняет прежние отчёты.

## Что осталось подключить

| Возможность | Android / UI | Backend / данные |
| --- | --- | --- |
| QR и шильдик | Декодер QR из кадров ARCore, распознавание шильдика и вызов поиска | `GET /equipment/resolve` уже есть. Для шильдиков нужны значения конкретных агрегатов. |
| Компьютерное зрение | Источник кадров ARCore, адаптер CV, координаты рамок, показ результата шага. Для пространственной метки нужна дополнительная проверка геометрии на телефоне. | Ветка интеграции сервиса распознавания не содержит. Команда должна выбрать способ подключения модели из отдельной CV-ветки. Для варианта с ноутбуком нужен `POST /vision/detect`. |
| Диагностика и паспорта | Показ режимных карт, документов, протоколов, оставшегося ресурса. Для признаков из истории понадобится состояние «открыт / устранён». | Есть уставки и упорядоченные шаги. Нужны правила связи «отклонение → вероятная неисправность → узел/шаг», реальные паспорта и регламенты. |
| Фото и экспорт | Захват фото, загрузка к шагу и экран скачивания PDF/XLSX | API загрузки, скачивания фото и обе выгрузки уже есть. |
| Поверки | Просмотр протоколов и загрузка поверок из интерфейса мастера | Сервер умеет принимать и хранить поверки. Для демо нужны реальные записи или явно помеченные примеры. |
| Сессия и история | Восстановление сессии и черновика после перезапуска. Сейчас токен хранится в памяти. | История привязана к оборудованию и автору; согласуйте сквозную историю при необходимости. |

При переносе стенда проверьте доступность ноутбука с телефона по Wi-Fi, полный осмотр и фиксацию метки при движении камеры. Демотелеметрия воспроизводит записи. Для живых показаний нужен источник данных и расчёт моточасов.
